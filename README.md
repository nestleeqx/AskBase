# AskBase — Telegram-бот, который отвечает по базе знаний

Бот отвечает клиентам компании строго по её документам: прайсу, списку врачей, ответам на частые вопросы и правилам записи. Если ответа в документах нет, честно говорит «Уточню у администратора» и передаёт вопрос человеку. Владелец загружает документы и смотрит диалоги в веб-админке.

**Демо-легенда:** стоматологическая клиника «Белая линия». Клиника, врачи, цены и адрес вымышлены.

> Проект в разработке. Описание, скриншоты и инструкция по запуску появятся по мере готовности.

## Демо-база знаний

`backend/app/seed/` — документы клиники и тестовый набор вопросов:

| Документ | Формат | Файл |
| --- | --- | --- |
| Прайс-лист | PDF | `docs/prajs-list.pdf` |
| Врачи и график работы | DOCX | `docs/vrachi-i-grafik.docx` |
| Частые вопросы: подготовка, гарантии, оплата | TXT | `docs/faq.txt` |
| Правила записи | страница сайта | `docs/pravila-zapisi.html` |

Исходные тексты PDF, DOCX и страницы лежат в `source/` (Markdown), файлы собирает `backend/scripts/build_demo_docs.py`.

## Как запустить локально

Нужен Docker.

```bash
cp .env.example .env   # впишите OPENAI_API_KEY; без ключа поиск работает упрощённо, по словам
docker compose up -d --build
```

- http://localhost:3000 — лендинг сервиса
- http://localhost:3000/login — вход в админку: гостем (без пароля) или владельцем клиники (пароль из `OWNER_PASSWORD` в `.env`). Гость видит демо-диалоги, свой тестовый чат и свой Telegram, его документы и настройки — только его. Владелец меняет документы и настройки бота для всех клиентов и видит все диалоги и заявки
- http://localhost:3000/admin/dialogs — диалоги клиентов с ботом в Telegram и ответ администратора
- http://localhost:3000/admin/bookings — заявки на запись, которые собрал бот
- http://localhost:3000/admin/chat — тестовый чат с ботом и разбор каждого ответа
- http://localhost:3000/admin/unanswered — «Бот не смог ответить»: вопросы, которых нет в базе; ответ отсюда попадает в документ «Ответы администратора», и бот начинает отвечать сам
- http://localhost:3000/admin/analytics — аналитика за неделю: диалоги по дням, доля вопросов с ответом, топ тем
- http://localhost:3000/admin/settings — настройки бота: приветствие, тон ответов, контакты
- http://localhost:3000/admin/documents — документы базы знаний, загрузка своих файлов и ссылок
- http://localhost:3000/admin/search — проверка поиска: какие фрагменты найдутся по вопросу
- http://localhost:8000/docs — API

При первом запуске документы клиники индексируются сами.

### Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) и впишите токен в `.env`: `TELEGRAM_BOT_TOKEN=…`.
2. `docker compose up -d --build bot` — бот сам опрашивает Telegram, вебхук и публичный адрес не нужны.
3. Напишите боту `/start`.
4. Чтобы ваша переписка появилась в «Диалогах», нажмите там «Подключить свой Telegram» и откройте бота по ссылке.
5. Уведомления менеджеру о заявках и вопросах без ответа: отправьте боту `/myid` и впишите число в `.env` — `MANAGER_CHAT_ID=…`, затем `docker compose up -d --force-recreate api bot`.

Бот отвечает на вопросы по документам, показывает цены по разделам прайса и присылает прайс-лист PDF, записывает на приём по шагам (имя → телефон кнопкой «Поделиться номером» → повод → удобное время) и передаёт запрос администратору.

Если бот не нашёл ответа или клиент нажал «Связаться с администратором», диалог в админке помечается «Ждёт ответа», а менеджеру приходит уведомление. Администратор отвечает из админки — сообщение уходит клиенту в Telegram, и бот в этом чате молчит 30 минут (или до кнопки «Вернуть боту»).

В «Диалогах» есть 8 вымышленных демо-диалогов — их ответы получены настоящей моделью скриптом `backend/scripts/build_demo_dialogs.py` и лежат в `backend/app/seed/demo-dialogs.json`. Бот написан на Bot API поверх httpx, без aiogram: ему нужен десяток методов Telegram, а один и тот же код работает и в опросе локально, и в вебхуке на Vercel.

Тесты бэкенда идут на Postgres с pgvector из того же compose:

```bash
docker compose up -d postgres
cd backend && uv run pytest
```

Проверка точности на тестовом наборе (нужен ключ в `.env`):

```bash
cd backend && uv run python scripts/evaluate.py --report eval-report.html
```

## Демо-база знаний — подробнее

`eval-questions.json` — 20 вопросов по документам с эталонными фактами и документом-источником и 5 вопросов вне базы, на которые бот должен передать вопрос администратору. Набор зафиксирован до настройки промптов: по нему считается точность ответов.
